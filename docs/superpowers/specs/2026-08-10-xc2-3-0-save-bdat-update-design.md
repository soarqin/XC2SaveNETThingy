# XC2 3.0 存档兼容与 BDAT 数据更新设计

## 目标

使 `XC2Bf2SaveNETThingy` 和 `XC2IraSaveNETThingy` 使用《异度神剑 2》3.0 版的角色、武器、技能和物品数据，并明确验证本篇与 Torna 存档的 3.0 兼容性。

更新结果必须满足以下要求：

- 两个编辑器继续共用 `XC2SaveNETThingy/XC2Data.db`。
- 数据库中的游戏数据来自可重复执行的 BDAT 转换流程，而不是手工修改 SQLite。
- 2.x 与 3.0 存档均可加载、无修改保存并重新加载。
- `romdata/` 仅作为本地输入，不修改、不提交，也不复制到应用输出目录。
- 保留当前工作区内尚未提交的 SDK-style 项目迁移改动。

## 已确认事实

### 存档布局

对 `romdata/2.0/main.elf` 与 `romdata/3.0/main.elf` 的逆向分析确认：

- 本篇解压后存档大小保持为 `0x126D90`。
- Torna 解压后存档大小保持为 `0x137B10`。
- 魔数、自定义 16 字节文件头、ZLIB 压缩流程、主要结构偏移、复制长度和扩展区没有变化。
- 核心存档函数经归一化比较后，仅发现全局地址和编译源码路径变化，没有字段重排。
- 偏移 `0x117390` 是 16 位存档版本值；游戏代码使用过 `15001` 和 `20001`，3.0 主程序没有引入新的布局版本值。

因此，不为 3.0 新增重复的存档模型。兼容性工作以识别条件、字段命名和回归验证为主。

### BDAT 资源

可用输入如下：

- `romdata/3.0/bdat`：亚洲版本篇 BDAT。
- `romdata/3.0/bdat_torna`：亚洲版 Torna 本地化 BDAT。
- `romdata/3.0U/bdat`：欧美版本篇 BDAT。
- `romdata/3.0U/bdat_torna`：欧美版 Torna 本地化 BDAT。

亚洲版与欧美版的 `common.bdat`、`common_gmk.bdat` 和 `lookat.bdat` 逐字节相同。欧美版的主要增量是 `gb` 等西文语言目录，不是另一套 gameplay 结构。

Torna 的 `bdat_torna` 由战斗、营地事件、事件、任务和对话文本组成，没有独立的 `common.bdat`。当前 Torna 编辑器不读取这些剧情文本；角色、武器、技能和物品数据仍来自本篇通用表。

### 当前项目数据流

两个编辑器运行时只读取可执行文件旁的 `XC2Data.db`，不直接读取 BDAT。源码仓库同时保存：

- `XC2SaveNETThingy/data/*.csv`：规范化数据源。
- `XC2SaveNETThingy/db/*.sql`：数据库表定义。
- `XC2SaveNETThingy/XC2Data.db`：运行时 SQLite 数据库。

现有项目没有 BDAT 导入器或自动化数据测试。数据库的 `PRAGMA integrity_check` 当前为 `ok`；已有错误外键定义会让 `PRAGMA foreign_key_check` 固定产生大量报告，因此本次不能以「零外键错误」作为验收门槛。

## 方案选择

### 方案一：手工修改现有 SQLite

直接比较并修改 `XC2Data.db`，实现速度较快，但无法稳定复现转换结果，也难以审查 ID、过滤规则和名称来源。后续版本更新仍需重新进行手工分析。

### 方案二：离线生成规范 CSV 与 SQLite

增加受版本控制的生成工具，以 BDAT 和现有人工数据为输入，生成规范 CSV、候选数据库和差异报告。该方案能够显式记录表映射、名称关联、ID 偏移、过滤规则和保留项。

这是选定方案。

### 方案三：应用运行时直接读取 BDAT

编辑器启动时解析 BDAT，可以避免提交生成后的数据库，但需要分发原始游戏数据，显著扩大运行时依赖与错误处理范围，也不符合当前应用结构。

## 数据更新架构

### 离线生成工具

在仓库内增加独立的数据生成工具及配置，负责以下工作：

1. 校验四个输入目录和 `romdata/bdat-toolset-win64.exe` 是否存在。
2. 校验亚洲版与欧美版通用 BDAT 的哈希一致性。
3. 将所需的通用表和 `gb` 英文本地化表提取到系统临时目录。
4. 根据受版本控制的映射规则生成项目格式的 CSV。
5. 从 `db/*.sql` 和规范 CSV 全新创建候选 SQLite，不在旧数据库上执行增量更新。
6. 生成机器可读和便于审阅的差异报告。
7. 通过所有校验后，才替换项目内对应 CSV 和 `XC2Data.db`。

工具不得写入 `romdata/`。临时目录和候选数据库不进入版本控制。

### 表与名称关联

结构化记录以 `common.bdat` 为准，英文显示文本以 `romdata/3.0U/bdat/gb` 为准。

本地化表通常是稀疏表或使用独立顺序。例如 `chr_dr_ms`、`btl_skill_bl_name` 和 `btl_arts_blsp_ms` 的行号不能直接视为项目 ID。生成工具必须按以下方式关联：

1. 从通用表读取记录 ID 及其 `Name` 数值索引。
2. 使用 `Name` 索引查找对应本地化表记录。
3. 将解析后的英文文本写入目标项目记录。
4. 缺少映射时，仅允许使用配置中明确列出的人工保留值；其他缺失均视为错误。

禁止按语言表行号批量覆盖数据库名称。

### 更新范围

更新当前两个编辑器实际使用的游戏数据，包括：

- 驾驶员、异刃和武器类型。
- 驾驶员武技、驾驶员技能、异刃武技、必杀技、战斗技能和场景技能。
- 武器与核心芯片关系。
- 饰品、辅助核心、收纳包道具、关键道具、情报、收藏品和其他现有物品类别。
- 花 JD、JS、JK 使用的 Poppiswap 类别。
- 属性、信赖等级、喜好类别及当前界面使用的其他枚举表。

不导入 Torna 的剧情、任务、营地事件和对话文本，也不新增当前界面未消费的游戏菜单文本表。

### ID 规则

项目通过合并 ID 空间区分物品类别。生成工具必须保留 `XC2Data.cs` 中已有的转换约定，包括：

- `10000`、`15000`、`17000`、`20000`。
- `25000`、`26000`、`30000`、`35000`。
- `40000`、`45000`、`50000`。
- `56000` 至 `60000` 的 Poppiswap 类别。
- 武器相关约 `5000` 的项目 ID 空间。

这些偏移是项目数据库主键布局的一部分，不能替换为 BDAT 原始 ID。生成报告必须同时显示原始 BDAT ID、目标项目 ID 和类别。

### 名称与人工数据策略

- 游戏对象的英文名称采用 3.0U `gb` 文本。
- 编辑器自身的窗体、FAQ、About 和内部提示文本保持不变。
- 无法从 BDAT 唯一解析的 Guest、DUMMY、占位记录和项目专用说明，沿用配置中明确列出的现有人工值。
- 已确认的 `[ML:Space]` 标记转换为空格并清理首尾空白。
- 发现其他未知本地化控制标记时停止生成，并在报告中列出表名、记录 ID 和原始文本。
- 空字符串、重复主键、重复目标 ID 和无法解析的名称索引均视为生成失败。

## 存档兼容设计

### 版本识别

共享序列化入口继续按解压后长度识别本篇和 Torna 布局，并增加魔数与完整长度校验。3.0 不新增存档类，也不复制现有模型。

不改变旧版本兼容分支。本篇编辑器仍拒绝打开 Torna 存档，Torna 编辑器仍只接受 Torna 布局。

### 存档版本字段

将 `Unk_0x117390` 表达为已确认的 16 位存档版本字段 `SaveVersion`。实现时必须保留原始字节序和无损写回，不对加载值进行自动升级或修正。

现有十六进制编辑能力可以保留，但界面标签和源码注释应说明这是存档版本值。除非获得新的逆向证据，不增加有效值限制。

### 其他未知字段

本次不把其他未知字段加入界面。只有满足以下条件的字段才可纳入后续实现：

- 主程序中存在稳定的读取和写入路径。
- 能确认数据类型、字节序、取值范围及其游戏语义。
- 本篇与 Torna 的布局差异已明确。
- 可以为旧存档提供无损 round-trip 验证。

## 生成失败与差异审查

生成工具在以下情况立即失败，并保留旧 CSV 与数据库：

- 输入文件或必需表缺失。
- 亚洲版与欧美版通用 BDAT 哈希不一致。
- 通用表结构与映射配置不一致。
- 本地化 `Name` 索引缺失或重复。
- 目标项目 ID 冲突、主键重复或项目 ID 超出预期范围。
- 出现未知本地化控制标记。
- 候选数据库无法打开或 `PRAGMA integrity_check` 不是 `ok`。

差异报告至少包含：

- 每张目标表的旧、新行数。
- 新增、删除和修改的主键。
- 原始 BDAT ID 到项目 ID 的映射。
- 名称、类型和关系字段的变化。
- 被人工保留或过滤的记录及原因。
- 已知外键报告的基线数量和本次增量。

删除记录、改变既有项目 ID 或产生新的外键违规时，不自动替换项目数据库。

## 验证

### 数据验证

- `PRAGMA integrity_check` 返回 `ok`。
- 所有目标表主键唯一且占位 ID 完整。
- 规范 CSV 与候选数据库逐表一致。
- 所有 `XC2Data` 查询均能执行，并且名称列不为空。
- 本篇与 Torna 界面使用的 ComboBox 数据源均包含其可用 ID。
- 两个 Release 输出目录中的 `XC2Data.db` 与源码数据库哈希一致。

现有错误外键定义不在本次数据更新中顺带重构。验收以既有 `foreign_key_check` 报告为基线，要求不得新增违规；外键定义修复应作为独立任务处理。

### 存档验证

为本篇 2.x、本篇 3.0、Torna 2.x 和 Torna 3.0 样本分别执行：

1. 加载存档。
2. 不修改任何字段并序列化。
3. 再次加载生成文件。
4. 比较解压后的结构长度、关键区域和未编辑字节。
5. 确认存档版本字段保持原值。

如果没有可提交的真实存档样本，则测试工具接受仓库外的样本目录，并在最终报告中记录哪些版本已实际验证、哪些仅完成结构级验证。真实存档不得提交。

### 应用验证

- 构建 `XC2SaveNETThingy.slnx` 和保留的 `XC2SaveNETThingy.sln`。
- 分别启动本篇与 Torna 编辑器，确认数据库加载和主要界面初始化没有立即失败。
- 检查驾驶员、武器、技能及各物品页的名称显示和 ID 选择。
- 验证本篇编辑器不会误接收 Torna 存档，Torna 编辑器不会误用本篇布局。
- 验证保存仍使用原有 16 字节头和 ZLIB 压缩流程。

## 交付内容

- 可重复执行的 BDAT 数据生成工具和映射配置。
- 更新后的规范 CSV 与 `XC2Data.db`。
- 数据差异与验证报告。
- 存档版本字段的明确命名和界面说明。
- 必要的自动化数据与 round-trip 检查。
- 两个编辑器的构建和启动验证结果。

## 范围边界

本次不包含以下工作：

- 将 Torna 剧情、任务或对话文本加入编辑器。
- 增加新的应用语言。
- 让应用在运行时读取或分发 BDAT。
- 修改无法确认语义的存档字段。
- 修复现有数据库的全部外键定义。
- 升级第三方依赖或重构无关界面。
- 修改或提交 `romdata/`。
